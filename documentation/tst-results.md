# Wazuh Security Testing Results

## 1. Objective

The objective of the testing phase was to verify that the Wazuh infrastructure was correctly receiving and displaying security-related events generated by the monitored Windows endpoint.

Testing was performed in a controlled personal laboratory environment.

## 2. Windows Endpoint Monitoring

The Windows laptop was successfully connected to the Wazuh infrastructure through the Wazuh Agent.

The endpoint appears in the Wazuh Dashboard as:

`windows_victin`

Events generated by the endpoint were successfully received and displayed by Wazuh.

## 3. Failed Authentication Testing

Controlled failed authentication attempts were performed on the Windows endpoint.

The resulting Windows security activity was detected by Wazuh and displayed in the dashboard.

This demonstrates that the Wazuh Agent can collect Windows authentication/security telemetry and forward it to the Wazuh server for analysis.

## 4. Windows Audit Failure Events

Wazuh detected Windows audit failure events.

Observed Wazuh rule:

* Rule ID: `60104`
* Description: `Windows audit failure event`
* Severity level: `5`

These events demonstrate the ability of the platform to identify and classify Windows security audit activity.

## 5. Windows Application Events

Wazuh also detected Windows application error events.

Observed Wazuh rule:

* Rule ID: `60602`
* Description: `Windows application error event`
* Severity level: `9`

These events demonstrate that the platform is receiving and analyzing Windows application-related security telemetry.

## 6. Additional Windows Events

The dashboard also displayed other Windows events, including:

* Software protection service activity
* Security/audit events
* Signature/report summary events

One observed rule was:

* Rule ID: `60608`
* Description: `Summary event of the report's signatures`
* Severity level: `4`

## 7. Kali Linux Testing

Kali Linux was used as a controlled security testing machine against the monitored Windows endpoint.

Network reconnaissance testing was performed using Nmap.

The purpose was to simulate activity that could occur during an internal security assessment.

The project documentation does not assume that every Windows event observed immediately after the test was caused by Nmap. Events are only attributed to a test when the relationship can be demonstrated reliably.
